# 📥 每日 arXiv 速览 (Daily arXiv) 细粒度编写规范

当用户投喂 arXiv 论文、说「帮我写今天的 arXiv 速览」「记一下今天看的几篇论文」时，必须遵循本规范。

---

## 0. 本领域的定位（决定一切取舍）

**每日区不是论文库，是漏斗。**

它的唯一目的是回答两个问题：

1. **今天有没有一篇论文值得我花时间？**
2. **没有的话，我今天要不要为这件事焦虑？**（答案是不用）

因此它<mark class="hl-key">**不承载论文内容**</mark>。所有真正要精读的东西，最终都落到 `docs/domains/*` 的正式笔记里。

> **铁律：一旦某篇论文被判为「值得精读」，立刻去对应 domain 建正式笔记，不要在每日区把它写成一篇小论文。** 每日区只留判断、链接和动作。

---

## 1. 文件位置与命名

| 项 | 约定 |
| :--- | :--- |
| 目录 | `docs/daily-arxiv/` |
| 每日文件 | `YYYY-MM-DD.md`（一天一个，**不可合并多天**） |
| 索引 | `docs/daily-arxiv/index.md` 表格，**按日期倒序**，新的一天插在**最前面** |
| 模板 | `docs/daily-arxiv/_template.md.txt`（**`.txt` 后缀是刻意的**，避免被 VitePress 构建成页面），用 `bash docs/daily-arxiv/new-day.sh` 复制 |

**不要**在 `config.mts` 的 sidebar 里为每天新增条目——侧边栏只保留索引页和最近几天，全量历史走 `index.md`。

---

## 1.5 每日固定检索轴（四维度准则，**不可省略、不可改写**）

<mark class="hl-key">**每天必须按下面四个维度各跑一次检索，四维全跑，不许只扫全量列表。**</mark>

| # | 维度 | 检索关键词（arXiv API，`cat:cs.CV` + 按 submittedDate 倒序） |
| :--- | :--- | :--- |
| **①** | **智能体 + harness** | `abs:"agent"` / `abs:"harness"` / `abs:"tool use"` / `abs:"agentic"` |
| **②** | **视频（视频模型 / 世界模型）** | `abs:"video generation"` / `abs:"video diffusion"` / `abs:"world model"` |
| **③** | **图像 AIGC 后训练** | `abs:"reinforcement learning"` AND (`abs:"image generation"` / `abs:"diffusion"` / `abs:"flow matching"` / `abs:"text-to-image"`) |
| **④** | **Fancy 下游任务 + benchmark** | `ti:"benchmark"` / `abs:"visual editing"` / `abs:"infographic"` / `abs:"agentic workflow"` |

推荐用 arXiv API 直查（比刷列表页准，且能拿到摘要）：

```
http://export.arxiv.org/api/query?search_query=cat:cs.CV+AND+(...)+&sortBy=submittedDate&sortOrder=descending&max_results=25
```

### 准则条款

1. **四维全跑**，即使某一维当天为空也要在速览里写明「本日该维度无命中」；
2. **每维最多挑 1 篇**进「今日值得看」，<mark class="hl-key">**这样「值得看」天然不超过 4 篇，超了就按 §3 判据砍到 3 篇**</mark>；
3. **记录检索到的最新批次日期**：arXiv 的 announce 与 submit 不同步，<mark class="hl-trick">**当天看到的最新一批可能是几天前的提交，必须如实标注，不要假装是「今日新论文」**</mark>；
4. 四维之间有交叉（如「视频 RL」同时命中②③）时，<mark class="hl-key">**归到更本质的那一维，并在括号里注明交叉**</mark>，不要重复计数。

## 2. 三段式结构（硬约束，不得增删小节）

```markdown
# 📥 YYYY-MM-DD arXiv 速览

> **日期** / **检索维度** / **最新批次**

## 📊 汇总表 · 四维度 N 篇        ← 🔴 必须在最上方，全维度一张表

| # | 论文 | 维度 | 机构 | 一句话大白话 |

## 🎯 今日值得看      <!-- ≤3 篇，五项完整 -->
## 📚 Read List · 四维度全量    <!-- ① ② ③ ④ 分节，五项完整 -->
## 👀 其余扫过        <!-- 一行大白话 -->
## ✅ 今日动作
```

### 2.0 顶部汇总表（**硬约束，位置固定在正文最上方**）

<mark class="hl-key">**每篇速览的第一屏必须是「一张表看完今天全部论文」。**</mark>

| 列 | 内容 |
| :--- | :--- |
| **#** | 序号 1..N，按维度分组连续编号 |
| **论文** | 标题 + arXiv ID（代码格式），🔥 标记「今天先读」 |
| **维度** | ①②③④ 之一，用 ① 智能体 / ② 视频·世界模型 / ③ 图像后训练 / ④ 下游任务·benchmark |
| **机构** | 简称，多机构用 `·` 分隔；无则写「未标注」 |
| **一句话大白话** | 与下方分节一致；<mark class="hl-trick">**表格里只放短版，不放长解释**</mark> |

::: danger 表格内不要用强调
<mark class="hl-trick">**汇总表里只允许 `**粗体**`，不要嵌 `<mark class="hl-key">` 高亮**</mark>——表格宽、嵌套 HTML 易导致渲染错乱，也影响扫读。详细判断留给下方「今日值得看」分节。
:::

::: tip 为什么要这张表
你每天只看第一屏。<mark class="hl-key">**汇总表负责「一眼看完」，分节负责「读完要挖的细节」**</mark>——两者职责不重叠，不要用分节代替汇总表。
:::

### 2.1 🎯 今日值得看（≤3 篇）

每篇**固定用下面这个四字段 + 一句话的格式**，字段顺序不许变、不许增删：

```markdown
### N. 论文标题（英文原名）

- **作者**：FirstAuthor, SecondAuthor, ...
- **机构**：机构名（arXiv 摘要/正文未标注时写「未标注」，**不要猜**）
- **代码**：链接；未开源写「未开源」
- **一句话**：<mark class="hl-key">**大白话，必须让人一眼看懂这篇论文做了什么**</mark>

**和我们什么有关**：点名某篇已有笔记或某个在做的方向
**下一步**：可执行动作
```

### 2.1.1 「一句话」的硬要求

| 要求 | 说明 |
| :--- | :--- |
| **纯大白话** | <mark class="hl-key">**不许出现论文原文术语**</mark>。禁止出现 reward hacking、mode collapse、elaborate XXX 之类没解释过的词 |
| **≤60 字** | 一行读完，不许分两句 |
| **讲清「输入什么 → 做了什么 → 得到什么」** | 数字可以留一个最亮眼的，不要罗列 |
| **不许写成摘要压缩** | <mark class="hl-trick">**不要把 abstract 翻译一遍**</mark>——用户要的是「一眼懂」，不是「读完懂」 |
| **写不出大白话 = 不够格进「值得看」** | 说明自己还没读懂，先放「其余扫过」 |

反例 → 正例：

| ✘ 反例 | ✔ 正例 |
| :--- | :--- |
| 提出 one-sided veto 以抑制 reward hacking 的复合偏好抑制机制 | 奖励模型学会解释后再打分，用的时候只扣分不加分，防止模型钻空子 |

### 2.1.2 👀 其余扫过

<mark class="hl-key">**一行一篇：标题 + 一句话大白话印象。有开源代码就把链接带上，不许展开。**</mark>这个小节的价值是「防重复扫」与「留个模糊印象」，不是摘要库。

::: danger 表格内的高亮写法（易踩坑）
**`<mark>` 与 `**` 必须在同一侧闭合**，否则 markdown-it 无法配对，直接让构建失败：

```markdown
✅ <mark class="hl-key">**加粗内容**</mark> 后接普通文字
❌ <mark class="hl-key">**加粗内容</mark>** 后接普通文字   ← 构建报错
```

写完记得检查：`<mark>` 与 `**` 各多少个、数量是否相等。

### 2.1.3 ✅ 今日动作

Checklist 形式，0–3 条：<mark class="hl-key">**要建的正式笔记 / 要跑的实验 / 存疑待验证的问题**</mark>。

---

## 3. 「值得看」的准入判据（满足任意一条）

| 标记 | 判据 |
| :--- | :--- |
| 🔥 | **撞上正在打的仗** —— 直接对应当前某个在写的方向 |
| 🧩 | **补上一块拼图** —— 某篇笔记里反复出现的「未公开 / 未验证」被它回答了 |
| ⚡ | **有一个能立刻跑的实验** —— 改一行代码就能验证 |

三条都不满足 → **进「👀 其余扫过」**。

---

## 4. 与正式笔记的闭环

判为「值得看」且决定精读时：

1. 在对应 domain 建正式笔记（走该 domain 的 spec，Part 分批写）；
2. 回到当日速览，把该条改成 `<mark class="hl-key">✅ 已建笔记 → [标题](../domains/xxx/yyy.md)</mark>`；
3. 在 `index.md` 的「动作」列填「已精读」。

这样从任何正式笔记都能反查它是哪天被发现的。

---

## 5. 本领域专属铁律

1. **不编造论文**：标题、arXiv 编号、作者、机构、代码链接必须来自用户投喂或可核验的原文；<mark class="hl-key">**拿不准的字段就写「未标注」/「未开源」，绝对不要猜机构**</mark>；
2. **不重复论文内容**：每日区禁止出现长公式推导、完整表格、实验数字罗列——<mark class="hl-trick">**那些属于正式笔记**</mark>；
3. **不新增小节**：三段式之外不加「总结」「延伸阅读」「参考文献」；
4. **索引必须同步**：写完每日文件后，**必须在同一次操作内**把日期插入 `index.md` 表格最前面，否则第二天打开就是断链；
5. **不复用标题**：不同日期允许不同论文占同一位置，不要写「今日精选 3 篇」这种无区分度的表头。
