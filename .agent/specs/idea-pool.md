# 💡 科研 Idea 灵感池细粒度记录规范

当用户让 Agent 记录一段突发的科研脑洞、奇思妙想、未经完全推导验证的直觉猜想时，Agent 必须将内容追加至 `docs/ideas/index.md` 中，遵循本规范。

---

## 1. 结构大纲标准

在 `docs/ideas/index.md` 的 `## 🌟 脑洞列表` 章节顶部或尾部追加，格式如下：

```markdown
### N. [用疑问句或反直觉论断拟定标题，例如：能否通过 X 实现 Y，从而省去 Z？]
- **记录时间**：YYYY-MM-DD
- **状态**：💡 [纯脑洞 / 观察] 或 🔬 [理论猜想] 或 🧪 [值得单卡跑个玩具 Demo] 或 ⏸️ [暂时搁置]
- **标签**：`#核心领域` `#技术点` `#Hypothesis`
- **灵感触发**：
  清晰说明受什么现象、论文、实验异常或跨界交叉技术启发（2~3 句话说明背景）。
- **核心猜想 (Hypothesis)**：
  形式化表达核心逻辑（若 A 成立，通过引入 B 操作，则 C 指标可以在不破坏 D 的前提下得到改善）。
- **潜在坑点与证伪路径**：
  从审稿人或实验失效的角度，指出最可能崩在哪里（如局部最优欺骗、高频闪烁、维度灾难），以及如何用最小成本（如单卡几小时代码）快速验证或证伪。
```

---

## 2. 编写要求
- 保持科研敏锐度，不要把简单的事实陈述当成 Idea，必须包含**清晰的假说（Hypothesis）与对比矛盾点**；
- 语言风格简明干练，拒绝学术套话，突出思想闪光点。
