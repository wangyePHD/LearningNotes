# 📥 每日 arXiv 速览 (Daily arXiv)

> **标签**：`arXiv` `Daily Scan` `Triage`
> **更新时间**：2026-10-13

每天扫一遍 arXiv，**只做两件事**：挑出 ≤3 篇真正值得看的，以及留下一行「其余扫过」的痕迹。

**这个专区不是论文库，是漏斗。** 值得精读的论文最终会落到 `🎲 RL-AIGC`、`🖼️ 图像与视觉`、`🎬 视频模型` 等正式笔记里；本页只留判断和链接，不重复内容——否则每天维护两份是坚持不下去的。

## 每日怎么用（60 秒流程）

1. **早上**：扫一遍 arXiv 列表，把标题过一遍；
2. **投喂**：把挑出来的丢给 Agent，格式随意，例如——
   > “帮我写今天的 arXiv 速览，这几篇值得看：A、B、C。另外顺手记一下 D、E、F。”
3. **Agent 自动**：在 `docs/daily-arxiv/YYYY-MM-DD.md` 生成当日速览，并把日期插到上方表格最前面；
4. **晚上**：只看「🎯 今日值得看」里的**下一步动作**，决定要不要开工。

新的一天从复制模板开始（模板是 `.txt` 后缀，不会被 VitePress 当成页面构建）：

```bash
bash docs/daily-arxiv/new-day.sh
```

## 三段式结构（固定，不要自由发挥）

| 小节 | 容量 | 每篇的写法 |
| :--- | :--- | :--- |
| **🎯 今日值得看** | **≤3 篇** | 固定五项：**标题 / 作者 / 机构 / 代码 / 一句话**（顺序不变、不增删） |
| **👀 其余扫过** | 不限 | 一行一篇：**标题 + 一句大白话 + 代码链接**，不展开 |
| **✅ 今日动作** | 0–3 条 | 要建的正式笔记、要跑的实验、存疑的问题 |

::: warning 「一句话」的硬要求
- **纯大白话**，不许出现论文原文术语（禁止 reward hacking、mode collapse 这类没解释过的词）
- **≤60 字**，一行读完
- 讲清「**输入什么 → 做了什么 → 得到什么**」，最多留一个最亮眼的数字
- <mark class="hl-key">**不许写成摘要压缩**</mark>——要的是「一眼懂」，不是「读完懂」
- **写不出大白话 = 自己还没读懂**，先放「其余扫过」
- 作者 / 机构 / 代码拿不准就写「未标注」/「未开源」，<mark class="hl-trick">**绝对不要猜机构**</mark>
:::

## 什么算「值得看」

满足**任意一条**才进「🎯 今日值得看」：

- 🔥 **撞上正在打的仗** —— 直接对应当前某个在写的方向（如 Arena-RL 的 Reward System、Sol-RL 的 rollout 预算）
- 🧩 **补上一块拼图** —— 某篇笔记里反复出现的「未公开 / 未验证」被它回答了
- ⚡ **有一个能立刻跑的实验** —— 能在现有训练框架里改一行就验证

三条都不满足 → **老老实实写进「👀 其余扫过」，一行完事**。

> 每日区最容易失败的原因不是没时间，而是**每天都硬凑 5 篇「值得看」**。留白是有价值的。

## 与正式笔记的闭环

```
每日速览  ──判断「值得看」──▶  domain 正式笔记（Part 分批精读）
   ▲                                  │
   └────── 回填链接 + 一句话 ◀────────┘
```

建完正式笔记后，回来在当日速览里把该条改成：

> ✅ 已建笔记 → [Arena-RL Part 1–10](../domains/rl-aigc/arena-preference-rubric-reward.md)

并在索引表的动作列填「已精读」。这样从任何一篇笔记都能反查到它是哪天被发现的。
